# 第5章 系统实现、可视化设计与实验分析

本章将系统实现、前端可视化设计和实验结果分析统一展开。与仅从算法流程描述系统不同，本章关注完整工程链路在本地视频分析任务中的可复现性、输出稳定性和可展示性。系统首先通过统一入口完成视频检查、设备选择、球轨迹检测、球员姿态估计和结果渲染；随后通过轨迹后处理与质量评估模块清理异常检测点，并将结构化结果导入前端仪表盘；最后基于8段测试视频，对球轨迹质量、后处理统计和球员运动指标进行定量分析。

为了保持实验叙述的严谨性，本章所有数据均来自本地流程已经生成的结构化输出和浏览器端验证结果。实验中未构建逐帧人工标注真值，因此评价重点放在工程可靠性、轨迹连续性、前端可展示性和运动统计可读性上。本文不将质量分数解释为检测模型相对于人工标注的准确率，也不报告依赖人工真值的precision、recall或mAP。

## 5.1 工程入口与运行流程

系统采用统一流程入口组织完整的视频分析任务。该入口在启动阶段会检查输入视频、模型资源、依赖脚本和输出位置，随后根据用户指定或自动推断的计算设备执行检测流程。系统支持在GPU、Apple图形加速设备和CPU之间切换，并分别为球轨迹检测和球员姿态估计设置设备选项。这样的设计使同一套流程能够适配不同实验环境，也便于在课程演示和本地复现实验中保持一致的调用方式。

在运行流程上，系统首先读取输入视频并确定分析样本编号，然后建立对应的输出空间。若用户提供已有球轨迹序列，系统可以跳过球检测阶段，直接进入后续分析；否则，系统调用球轨迹检测模型生成原始轨迹。随后，轨迹后处理模块根据场地区域、静态锁定、跳点和短缺口规则修正检测序列。完成球轨迹处理后，系统执行球员姿态估计与运动统计，生成视频叠加结果和结构化统计信息。若前端导出开关处于启用状态，系统会进一步整理视频、轨迹、球员、运动和质量数据，供浏览器端仪表盘读取。

这一流程的优势在于将推理、后处理、统计和前端导出封装为连续链路。对于实验章节而言，这意味着表格中的帧数、时长、质量分数、后处理数量和运动距离均可从同一套输出中复核，减少了手工整理带来的不一致风险。

## 5.2 关键模块与文件组织

系统实现可概括为五类核心模块：统一调度模块、球轨迹推理模块、轨迹后处理模块、球员运动统计模块和前端数据导出模块。统一调度模块负责组织完整流程，并协调输入检查、设备设置和输出生成；球轨迹推理模块负责定位视频帧中的羽毛球；轨迹后处理模块负责拒绝异常点、平滑可信轨迹并恢复短时缺口；球员运动统计模块负责提取球员位置、计算速度和累计距离；前端数据导出模块负责将离线分析结果转换为浏览器端可读取的数据结构。

**表4 关键模块与功能对应关系**

| 模块 | 功能 | 主要输出 |
|---|---|---|
| 统一调度模块 | 调用完整分析链路，检查输入、资源和输出位置 | 分析任务输出空间 |
| 球轨迹推理模块 | 对视频帧中的羽毛球位置进行检测 | 原始球轨迹序列 |
| 轨迹后处理模块 | 拒绝误检、修正跳点并恢复短缺口 | 精炼球轨迹序列与质量报告 |
| 球员运动统计模块 | 估计球员位置并计算运动距离、速度等指标 | 球员轨迹与运动统计 |
| 前端数据导出模块 | 整理视频、轨迹、质量和统计数据 | 前端可视化数据包 |

表4说明，本文系统由多阶段模块共同构成可视分析流程，超出了单一检测模型调用的范围。球轨迹推理提供初始观测，轨迹后处理提高数据稳定性，球员统计扩展运动分析维度，前端导出则将离线结果组织为可交互界面。各模块之间形成从视频输入到分析展示的连续数据路径。

## 5.3 前端可视化界面

[插入图4：前端可视化仪表盘界面]

**图4 前端可视化仪表盘界面**

图4展示了系统前端界面。界面左侧保留视频播放上下文，中间展示球场空间视图，右侧呈现检测时间线和质量信息；顶部统计卡片则概括帧数、帧率、时长、球可见率、缺失段、球员距离和最高速度。该设计使用户能够同时观察视频画面、轨迹位置、运动趋势和检测可靠性。

前端界面主要由五个面板构成。第一，视频播放区提供原始画面、叠加结果和最终结果三种视图，便于比较模型输出与实际画面之间的关系。第二，球场空间视图将球员位置和羽毛球轨迹投影到标准球场坐标中，并支持轨迹视图和热力图视图切换。第三，时间序列分析面板呈现速度曲线、距离曲线和置信度曲线，用于观察运动强度和检测状态随时间的变化。第四，检测时间线以逐帧颜色编码展示有效检测、低置信度和缺失目标，有助于快速定位异常帧。第五，质量统计面板汇总质量等级、质量分数、球可见率、空间映射率、球员可见率和缺失段列表。

这一界面组织方式参考了视觉分析系统常见的“上下文-细节-统计”结构。视频画面提供语义上下文，球场视图提供空间关系，时间线和速度曲线提供动态变化，质量面板提供可靠性解释。通过多视图联动，用户能够从单帧、片段和整体三个层面理解系统输出。

## 5.4 图像结果展示

[插入图5：原始视频帧与球轨迹输出示例]

**图5 原始视频帧与球轨迹输出示例**

图5对比展示了原始输入帧和球轨迹输出效果。羽毛球在比赛视频中通常尺寸很小，且容易受到运动模糊、遮挡、灯光、字幕区域和背景高亮的影响。即使检测模型能够在多数帧中定位目标，原始轨迹仍可能包含场地外误检、固定背景点和运动不连续跳点。因此，后续轨迹质量控制具有基础作用，直接影响前端轨迹展示的可信度。

从可视化角度看，单个异常点即可在轨迹线上形成明显折返，连续静态误检则可能使羽毛球轨迹固定在背景区域。为避免这些异常被误读为真实运动，系统在进入前端展示之前对球轨迹进行规则化清理，并通过质量分数和质量等级向用户提示当前轨迹的展示可靠性。

评价指标分为两类。第一类为球轨迹质量指标，包括质量分数、质量等级、可见率、最大缺失间隔和插值率。质量分数用于综合描述轨迹连续性、异常点比例和短缺口恢复情况；质量等级用于判断轨迹是否适合进入前端展示；可见率表示最终有效球轨迹帧占总帧数的比例；最大缺失间隔刻画最长连续丢失片段；插值率反映短缺口恢复在有效轨迹中的占比。第二类为球员运动统计指标，包括双人累计跑动距离、最高速度和平均速度，用于描述片段中的运动负荷和回合强度。

由于缺少逐帧人工真值，本文不将这些指标用于证明检测算法达到某种绝对精度。质量分数的作用在于说明轨迹是否具备工程展示条件，运动统计的作用在于描述球员移动趋势。这样的评价方式与系统复现实验目标一致，也与前端可视分析任务的需求相匹配。

## 5.8 讨论与适用范围

实验结果表明，系统在8段测试视频上均能生成Green等级球轨迹和可读的球员运动统计。然而，当前系统仍存在需要明确说明的边界。首先，原始球检测结果仍会包含误检和跳点，前端可视化对这类错误非常敏感，因此轨迹后处理是提高工程可信度的重要环节。其次，质量分数来自后处理统计和轨迹连续性约束，能够说明轨迹是否适合展示，但不能替代人工标注真值下的检测精度评估。第三，球场单应性将场地近似为平面，球员脚点较适合投影到该平面，而羽毛球飞行存在高度变化，因此羽毛球物理速度会受到投影误差影响。相比之下，球员移动距离和速度的解释更稳健。

从适用范围看，本文系统适合用于课程展示、教学演示和初步视频分析。它能够将羽毛球轨迹、球员运动和质量信息组织为可交互界面，并为后续人工检查提供结构化线索。当前结果仍不宜直接声明为专业比赛战术系统、具有人工真值验证的最优检测算法或实时商业系统。后续工作可以从三个方向改进：建立逐帧人工标注集以评估检测精度；引入更稳健的三维或多视角球速估计方法；扩展更多真实比赛场景以验证跨视角、跨光照和跨视频质量的泛化能力。

综合来看，本章从工程实现、前端设计和实验分析三个层面验证了系统的可复现性与可展示性。统一流程入口保证了分析链路的连续性，前端多视图界面增强了结果解释能力，定量实验则说明轨迹后处理和质量评估能够为系统输出提供必要的可靠性约束。
